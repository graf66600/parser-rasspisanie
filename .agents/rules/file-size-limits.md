# Правила разработки и стандарты проекта

## 1. Ограничение размера файлов и модульность (Критическое правило)
- **Комфортный размер файла — до 300 строк.**
- Большие файлы необходимо разделять на меньшие, логически изолированные модули и компоненты.
- По возможности придерживаться этого правила при написании нового кода и рефакторинге существующего.
- Логику разделять по принципу единственной ответственности (Single Responsibility):
  - Выносить типы, константы, утилиты и хелперы в отдельные файлы.
  - Декомпозировать интерфейс на самостоятельные модули/компоненты.
  - Не создавать монолитных файлов, дробить большие скрипты, серверные обработчики и стили на связанные подмодули.

## 2. Адаптивность и мобильный интерфейс (Mobile-First)
- Обеспечивать полную адаптивность под мобильные устройства (начиная с ширины экрана 320px).
- Текст, таблицы, списки студентов и элементы форм никогда не должны выходить за границы контейнеров.
- Использовать `word-break: break-word`, гибкие сетки (`flex`, `grid`) и сенсорно-комфортные зоны нажатия (touch targets от 36-44px).

## 3. Синхронизация веток и публикация PWA (GitHub Pages)
- **Обязательная синхронизация веток `main` и `gh-pages`:**
  - При любых обновлениях клиентской части PWA (расписание, КТП, темы занятий, стили, Service Worker, скрипты) изменения ОБЯЗАТЕЛЬНО должны отправляться в **обе ветки**: `main` и `gh-pages` (`git push origin main` и `git push origin gh-pages`).
  - Мобильное веб-приложение на смартфонах пользователей загружается через GitHub Pages из ветки `gh-pages`. Без синхронизации `gh-pages` телефон не получит обновления.
  - Статические файлы приложения в корне (`index.html`, `app.js`, `sw.js`, `styles.css`, папки `css/`, `js/`, `data/`) и в папке `public/` должны быть идентичны и синхронизированы на 100%.

### 1.2. Стек технологий и конфигурация сборки
- **Клиентская часть PWA:** Native JavaScript (ES Modules, ES2022+), CSS Grid/Flexbox, HTML5 Semantic Elements. Отсутствие тяжеловесных фреймворков (React/Vue/Angular) обеспечивает мгновенный холодный старт (менее 100 мс) даже на энергоэффективных смартфонах и встроенных процессорах сенсорных терминалов.
- **Серверная часть и инструменты парсинга:** Node.js (версии 20 LTS / 22), TypeScript 5.8, tsx для высокопроизводительного выполнения без промежуточной компиляции, Zod для валидации структур расписаний, xlsx и pdf-parse для разбора документов.
- **Облачная база данных и Realtime:** Supabase (PostgreSQL 15+, REST API PostgREST, Realtime WebSocket engine).
- **Операционная система терминала:** Astra Linux / Rosa Fresh (отечественное ПО), графическая среда Fly/X11.

## 2. ПОЛУЧЕНИЕ ДАННЫХ И СИНХРОНИЗАЦИЯ

### 2.1. Источники данных приложения
1. **Матрица расписания (`data/schedules_all.json` и `data/schedule.json`):**
   - Формируется парсером из официальных файлов учебной части (.xlsx, .pdf).
   - Загружается клиентским кодом (`js/state.js`, `js/kioskData.js`) при старте приложения с использованием стратегии кэширования: сначала данные считываются за 0 мс из `localStorage` / Cache API, а затем асинхронно актуализируются по сети.
2. **Журнал преподавателя и посещаемость (`journal_entries` в Supabase):**
   - Хранятся в облачной реляционной базе данных Supabase.
   - Клиент выполняет прямые REST-запросы к PostgREST API с автоматическим сохранением локального снимка в `localStorage` (`pwa_journal`).

### 2.2. Механизм подписки на изменения (Supabase Realtime)
В модуле `js/supabaseSync.js` реализована подписка на входящие события изменений базы данных через постоянный WebSocket-канал:

```javascript
// Фрагмент js/supabaseSync.js: Реактивная подписка на изменения через WebSocket
export function setupRealtimeSubscription() {
  const client = getSupabaseClient();
  if (!client || realtimeChannel) return;

  try {
    realtimeChannel = client
      .channel('pwa-journal-realtime')
      .on(
        'postgres_changes',
        { event: '*', schema: 'public', table: 'journal_entries' },
        (payload) => {
          handleRealtimePayload(payload);
        }
      )
      .subscribe((status) => {
        if (status === 'SUBSCRIBED') {
          console.log('⚡ Supabase Realtime: подписка на журнал активна');
        }
      });
  } catch (e) {
    console.warn('Realtime subscription init failed:', e);
  }
}
```

При наступлении событий `INSERT`, `UPDATE` или `DELETE` состояние приложения (`state.journalEntries`) обновляется реактивно без перезагрузки страницы, синхронизируя изменения между телефоном преподавателя и другими клиентами.

### 3.2. Архитектура Service Worker (`sw.js`, версия v42)
Используется комбинированная стратегия обслуживания запросов:
1. **Network-First с коротким таймаутом (1.2 с) для HTML-документов:** гарантирует, что пользователь всегда получит свежую версию приложения при наличии устойчивой сети, а при медленном соединении или офлайне мгновенно откроет закэшированный интерфейс.
2. **Stale-While-Revalidate для статических ресурсов (CSS, JS, JSON, SVG):** запрос мгновенно возвращается из Cache API (0 мс), после чего в фоне запрашивается обновление с сервера и сохраняется в кэш.

```javascript
// sw.js: Обработка статических ресурсов со стратегией Stale-While-Revalidate
self.addEventListener('fetch', (event) => {
  if (event.request.method !== 'GET') return;
  if (event.request.url.includes('/api/')) return;
  if (!event.request.url.startsWith(self.location.origin)) return;

  // Stale-While-Revalidate: отдача из кэша + фоновое обновление
  event.respondWith(
    caches.match(event.request, { ignoreSearch: true }).then((cachedResponse) => {
      const fetchPromise = fetch(event.request)
        .then((networkResponse) => {
          if (networkResponse && networkResponse.status === 200) {
            const clone = networkResponse.clone();
            caches.open(CACHE_NAME).then((cache) => cache.put(event.request, clone));
          }
          return networkResponse;
        })
        .catch(() => cachedResponse);

      return cachedResponse || fetchPromise;
    })
  );
});
```

## 5. РЕЖИМ ИНФОРМАЦИОННОГО КИОСКА (СЕНСОРНЫЙ СТОЛ 43″)

### 5.1. Архитектура контроллера киоска (`js/kioskView.js`)
Режим киоска спроектирован специально для больших сенсорных экранов (1920x1080) коллективного пользования:
1. **Виджет цифровых часов и даты:** крупные часы высокой четкости с секундной стрелкой и текущей датой на русском языке.
2. **Индикатор звонков (Bell Status Pill):** в реальном времени анализирует системное время и отображает состояние («Идёт 2 пара, до окончания 25 мин», «Большая перемена», «Занятия завершены»).
3. **Автоматический сброс при бездействии (Inactivity Watchdog):**
   - Установлен таймер бездействия `INACTIVITY_TIMEOUT_SEC = 60`.
   - Любое касание экрана (`pointerdown`), движение мыши или нажатие клавиши сбрасывает счетчик.
   - Если в течение 60 секунд пользователь не совершал действий, киоск автоматически закрывает открытые модальные окна расписаний групп и возвращается на стартовую вкладку «Сейчас (Live)».
4. **Полноэкранный режим (Fullscreen API):** переключение в полноэкранный режим по клику или параметру URL `?kiosk=1`.

```javascript
// Фрагмент js/kioskView.js: Автоматический сброс при бездействии
export function resetInactivityTimer() {
  secondsUntilReset = INACTIVITY_TIMEOUT_SEC;
  updateResetIndicator();

  if (inactivityTimer) clearInterval(inactivityTimer);
  inactivityTimer = setInterval(() => {
    if (!isKioskActive) return;
    secondsUntilReset--;
    updateResetIndicator();

    if (secondsUntilReset <= 0) {
      if (currentKioskSubtab !== 'live' || modalEntity) {
        closeKioskScheduleModal();
        switchKioskSubtab('live');
      }
      secondsUntilReset = INACTIVITY_TIMEOUT_SEC;
    }
  }, 1000);
}
```

   - Режим интерактивного киоска: `https://graf66600.github.io/parser-rasspisanie/?kiosk=1`
2. **Аппаратный комплекс сенсорного киоска:**
   - **Модель:** Электронный интерактивный сенсорный стол «SUPERIOR» (ИП Куликов Д.А., г. Симферополь).
   - **Дисплей:** Сенсорный экран 43″, разрешение FullHD (1920x1080), мультитач до 10 одновременных касаний, яркость 450 нит.
   - **Процессор:** Intel Core i7-10700F (8 ядер, 16 потоков, до 4.8 ГГц).
   - **Оперативная память:** 32 ГБ DDR4 3200 МГц.
   - **Материнская плата:** отечественная системная плата «iRU» ЛПГР.469559.012 (реестр промышленной продукции Минпромторга РФ).
   - **Видеокарта:** Palit GeForce RTX 3050 8 ГБ GDDR6.
3. **Программное окружение киоска:**
   - **Операционная система:** Отечественная ОС Astra Linux (Special / Common Edition) / Rosa Fresh, графическая подсистема Fly/X11.
   - **Браузер:** Chromium в режиме Kiosk (`--kiosk --touch-events=enabled --disable-pinch --incognito`).
   - **Автозапуск:** Shell-скрипт `kiosk-astra.sh` и конфигурационный файл `schedule-kiosk.desktop` для службы автозапуска X11.
4. **Место установки и внедрения:**
   - Образовательная организация: **Генический медицинский колледж** (г. Геническ, Херсонская область).
   - Локация: Главный холл / фойе учебного корпуса колледжа.
5. **Текущая версия ПО:** PWA v42.
6. **Охват пользователей:** около 350 студентов дневного и очно-заочного отделений (специальности «Лечебное дело», «Сестринское дело», «Фармация»), а также преподавательский состав колледжа.

# Какие материалы прислать из программы просмотра расписания

Программа для телефона и информационного киоска будет описана в §3.3 ВКР («Разработка мобильного PWA-приложения преподавателя и механизма реактивной синхронизации данных»). Чтобы текст, листинги и рисунки совпадали с кодом, нужны материалы ниже.

Формат: один zip-архив без папок node_modules, dist, build, .git или PDF, как в прошлый раз.

## 1. Общие сведения (обязательно)

- [ ] Дерево каталогов проекта (вывод `tree -L 3` или скриншот).
- [ ] README, если есть.
- [ ] package.json (или аналог для другого стека: requirements.txt, composer.json и т. п.).
- [ ] Конфигурация сборки: vite.config.ts / webpack.config.js / tsconfig.json.

## 2. Получение данных и синхронизация (обязательно)

- [ ] Файл, где программа загружает расписание: откуда берет данные (таблица schedule_data в Supabase, отдельный JSON, API основной программы).
- [ ] Код подписки на изменения (Supabase Realtime, периодический опрос, WebSocket) и интервал обновления.
- [ ] Файл клиента Supabase (если используется), ключи заменить на «XXX».
- [ ] Ответ в двух словах: есть ли вход пользователя или программа открыта всем.
- [ ] Типы данных (types.ts или аналог), если они отдельные от основной программы.

## 3. PWA и офлайн-режим (обязательно)

- [ ] manifest.json (или manifest.webmanifest).
- [ ] Service worker (sw.js) или настройки vite-plugin-pwa / Workbox.
- [ ] Код регистрации service worker.
- [ ] Код сохранения данных на устройстве (localStorage, IndexedDB, Cache API) и показа расписания без сети.
- [ ] Иконки приложения (список файлов и размеры).

## 4. Экраны для телефона (обязательно)

- [ ] Экран выбора группы, преподавателя или аудитории.
- [ ] Вид расписания на день.
- [ ] Вид расписания на неделю.
- [ ] Маршрутизация (роутер) или способ переключения экранов.
- [ ] Сохранение выбора пользователя (последняя группа или преподаватель).

## 5. Режим информационного киоска (обязательно)

- [ ] Компонент экрана киоска.
- [ ] Код автообновления данных.
- [ ] Автопрокрутка или смена групп/корпусов по таймеру.
- [ ] Полноэкранный режим, возврат на главный экран при бездействии.
- [ ] Подсветка текущей и следующей пары, текущее время и дата.
- [ ] Настройки киоска (какие группы показывать, скорость смены, корпус), если есть.

## 6. Адаптивная верстка (обязательно)

- [ ] CSS-файлы или модули стилей с медиазапросами.
- [ ] Отдельные стили для телефона и для большого экрана, если они разделены.

## 7. Дополнительные функции (если есть)

- [ ] Показ замен и изменений расписания (выделение измененных пар).
- [ ] Уведомления пользователю (внутри приложения или push).
- [ ] Поиск свободных аудиторий.
- [ ] Темная тема, ночной режим экрана киоска.
- [ ] Отображение звонков, сокращенных дней, практик.

## 8. Иллюстрации (обязательно)

- [ ] 2–3 скриншота с телефона: выбор, день, неделя.
- [ ] 1–2 скриншота или фото экрана киоска.
- [ ] Скриншот работы без сети (если офлайн-режим есть).

## 9. Сведения о внедрении (желательно)

- [ ] Где опубликована программа (адрес сайта или хостинг).
- [ ] На чем работает киоск: экран, компьютер или мини-ПК, операционная система, браузер, запущен ли Chrome в режиме киоска.
- [ ] Где установлен киоск в колледже.
- [ ] Версия программы и дата начала использования.
- [ ] Примерное число пользователей (студенты, преподаватели), если известно.

## Чего не присылать

- Файлы .env, ключи API, пароли, токены, строки подключения к базе данных.
- Персональные данные студентов.
- Если ключ записан прямо в коде, заменить его на «XXX».

## Что будет сделано после получения

- §3.3 будет написан по реальному коду программы просмотра: листинги, рисунки, таблица компонентов.
- План доработки будет дополнен:
  - программа просмотра должна работать с новыми правилами доступа только на чтение;
  - уведомления об изменениях лучше делать в ней;
  - PWA доводится в ней, если она уже частично готова.
